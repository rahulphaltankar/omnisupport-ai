# Decision log

Format: **ID — decision** · rationale / alternatives rejected · epic. Appended as work proceeds (newest last).

| ID | Decision | Rationale / alternatives rejected | Epic |
|---|---|---|---|
| D01 | Repository root is the student pack folder (`Student_Project_Pack/Student_Project_Pack`). The sibling `Instructor_Assessment_Pack` is never read, copied or committed, and is git-ignored by name. | Student-facing materials only; the root already holds the supplied starter structure, tests and CI. | 0 |
| D02 | Prediction moment **T0 = ticket creation, before triage**. `issue_category`, `priority`, `customer_sentiment`, `refund_*`, `csat_score`, `resolution_status_after_7d` and `final_agent_disposition` are excluded from T0 models. | Triage labels are human outputs; sentiment is documented as "derived from post-contact review"; CSAT policy (KB 29) forbids it at creation; `final_agent_disposition` equals the target. The alternative (allow `issue_category`, a "T1 post-triage" model) is quantified as an ablation instead of silently adopted. | 1 |
| D03 | Temporal split: train Jan–Aug, validation Sep–Oct, test Nov–Dec 2025; CV inside train is `GroupKFold` by customer. | Mirrors deployment (train on the past, score the future); a random split would let one customer's earlier and later tickets straddle sets. Customer overlap is reported, not hidden. | 1 |
| D04 | Sensitive attributes (age band, language, accessibility flag) are not model features; they are used for subgroup evaluation, with an ablation quantifying the effect of excluding them. | Data minimisation and fairness; they are not needed for T0 routing. | 2 |
| D05 | Exact duplicate rows (4,000) are removed before any split. Rows are *not* dropped for outliers; outliers are winsorised at the **train** 99.9th percentile inside the pipeline. | Duplicates across a split inflate scores; extremes look like rare real orders; clip bounds are learnt from train only. | 1 |
| D06 | Regression trains on a winsorised target (train p99.9) but is *evaluated on raw hours*. MAE is primary, RMSE reported. | RMSE is dominated by a few extreme times up to 899h. | 2 |
| D07 | `starter_code/**` files stay at their original paths as thin adapters over `src/omnisupport/**`, so the supplied starter tests exercise the real implementation. | Retains the supplied contract/test layout while keeping real code importable and testable. | 3 |
| D08 | Two data-presence starter tests skip (with an explicit reason) when the raw shards or subset are absent; they run and pass locally. | Raw data is intentionally not committed, so a fresh CI checkout cannot contain it. All other starter tests are untouched. | 4 |
| D09 | `requirements.txt` is unchanged. `requirements-ci.txt` is extended (numpy, pandas, scikit-learn, pyarrow, joblib, pillow) and a new `requirements-serve.txt` (CPU torch) is used by Docker. | CI must run meaningful tests, not only API contracts; default torch/CUDA wheels would make the image multi-GB. | 4 |
| D10 | No LLM API key exists in the build environment. The LLM benchmark uses real local instruct models (Qwen2.5-0.5B/1.5B-Instruct) via `transformers`. An Anthropic provider is implemented behind the same interface and covered by stub-client tests only. | Never fabricate API metrics; local runs give genuine latency/token measurements. Cost is an *estimated compute cost* (assumptions in `reports/llm_benchmark.md`). | 5 |
| D11 | The default runtime provider is `rules` (deterministic extractor). LLMs are opt-in via environment variables. | Offline, reproducible, safe fallback and CI-friendly; the same pydantic validation gates every provider. | 5 |
| D12 | RAG answers are **extractive and cited** (top evidence sentences) with a calibrated abstention score; no free-form generation by default. | Faithfulness over fluency; small local LLMs hallucinate policy numbers. | 5 |
| D13 | The agent planner is deterministic (regex + schema-validated tool calls), not an LLM loop. | Testable, no prompt-injection path to tools; an LLM can be added later behind the same gate. | 5 |
| D14 | The UI is Gradio (already pinned in `requirements.txt`). | No new dependency. | 6 |
| D15 | Local environment is Python 3.14 with torch 2.11 / scikit-learn 1.8, while the pinned baseline is Python 3.12 / torch 2.13 / scikit-learn 1.9. Code avoids version-specific features, CI on Python 3.12 is the arbiter, model pickles record library versions, and the API degrades gracefully on mismatch. | The pinned stack could not be installed locally; disclosed instead of claiming parity. | 4 |
| D16 | Large artefacts (raw data, images, fine-tuned transformer and ResNet weights) are git-ignored. Metadata, metrics, figures, small tabular checkpoints and the small serving model are committed. | Brief: do not resubmit raw data/images; keep the repo light. | 0 |
| D17 | Policy floor added in code after the benchmark exposed unsafe raw model output; benchmark rows are kept as raw behaviour and labelled as such. | Do not hide failures; fix the control, not the table. | 6 |
| D18 | RAG uses a calibrated dense threshold (0.34) and a TF-IDF fallback (0.20 with an out-of-vocabulary coverage penalty). Conflict detection only fires for return-policy day-window differences or when the question asks about conflicts. | Earlier broader detection produced false conflicts; thresholds chosen on dev probes. | 7 |
| D19 | Serve the CNN with low-confidence routing; ResNet18 is the documented alternative for varied photos. | CNN is faster and perfect in distribution; ResNet18 is more robust to blur, rotation and darkness. | 4 |
| D20 | Deploy the simple (logistic/tree) classical model, not the NN or DistilBERT. | No accuracy gain from the heavier models; cheaper and explainable. | 2/5 |
| D21 | Agent `requires_approval` depends only on amount above GBP 100; partial-refund customer confirmation is a separate flag. The 20 % partial refund is an assumed placeholder. | Keeps the approval boundary simple and testable. | 8 |
| D22 | Docs and code claims marked unverified when not run (Docker build, hosted CI, hosted LLM). | Brief forbids fabricated metrics. | 10 |
| D23 | Public repository publication is held until the owner confirms account, name and visibility. | Brief requires confirmation; `gh` login exists but nothing else was specified. | 11 |
